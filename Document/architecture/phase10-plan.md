# Phase 10 計画 — 月次請求・キックバック

## 目的

契約に紐づく **エンドユーザー向け請求（ルートBP発行）** と **BP間キックバック（多段）** を、月次自動生成で管理する。  
Phase 7 の手動請求発行は本機能に統合して廃止する。  
旧デザイン刷新は **[Phase 11](phase11-plan.md)**。

## 合意済み要件

### カスタマー請求

| 項目 | 合意 |
|------|------|
| データ | 既存 `invoices` / `invoice_lines` を拡張 |
| BP二系統（案A） | `issuer_bp_id`＝**ルートBP（発行主体）**、`owning_bp_id`＝**管理BP** |
| 単価 | 管理BP設定→価格承認済み `unit_price`。変更は申請必須 |
| 自動生成 | 契約単位。**デフォルト ON**（`auto_invoice_enabled`） |
| 請求停止 | **別フラグ** `billing_suspended`。activated のまま停止可。UIで強調 |
| 操作権限 | admin / 管理BP。カスタマーは参照のみ |
| 生成方針 | 確定後は触れず翌月分のみ。**取下げ**後は同月再生成可。入金済は取下げ不可 |
| スケジュール | **毎月N日** または **月末** ＋ **時刻** を管理者画面で設定（既定: 月末 / 10:00 Asia/Tokyo） |
| 請求月の帰属 | バッチ実行日の年月＝請求月（例: 3/31 実行 → **3月分**） |
| ルートBP | 契約管理BPから親を辿った **最上位BP** |
| 対象 | `activated` ∧ 自動ON ∧ 停止OFF ∧ 請求月 ∈ [first, final] |
| 品目 | イニシャル＝開始月のみ／ランニング＝毎月。請求開始年月を尊重 |
| 終了 | `final_billing_year_month` 超過で停止。月末締め・翌月払い |
| 手動発行 | **廃止**（本機能へ統合） |
| 再計算 | `recalc_on_price_change` **デフォルト ON**。価格変更承認後、発行済・未入金を再計算 |

### イニシャルのシステム請求

| 項目 | 合意 |
|------|------|
| 粒度 | **契約全体**と**明細単位**の両方 |
| 契約 | `bill_initial_in_system`（契約デフォルト） |
| 明細 | `contract_items.bill_initial_in_system`（NULL時は契約値を継承） |
| OFF時 | 当該イニシャルはルート発行の請求に載せない。中間BPが独自に請求 |

### エンドユーザー請求の無効化（中間BPが金額を持つケース）

| 項目 | 合意 |
|------|------|
| 粒度 | **契約単位**と**明細単位**の両方 |
| 契約 | `end_user_billing_disabled` |
| 明細 | `contract_items.end_user_billing_disabled`（NULL時は契約値を継承） |
| 操作者 | **品目の管理者**（BP品目→`items.owning_bp_id`、管理者品目→admin）、その **上位BP**、または **admin** |
| admin | BP方針を **オーバーライド可能** |
| 契約全体が無効 | カスタマー請求なし／キックバックなし |
| 明細のみ無効 | その明細は請求・キックバック対象外。他明細は通常どおり（同一請求内に混在しうる） |
| UI | 提供中×EU請求無効／請求停止を区別して表示 |

### キックバック

| 項目 | 合意 |
|------|------|
| 伝票 | カスタマー請求と **別**（`kickback_invoices`） |
| 税 | 税別計算、税率は明細設定、画面で税込併記 |
| 多段 | 必須。親子区間の差額 |
| 式 | `Root→Mid = W(Mid,Leaf) − W(Root,Mid)`／`Mid→Leaf = U − W(Mid,Leaf)`（上位→下位へ支払） |
| 負の差額 | **エラー**。画面に計算内訳と **絶対値** を表示 |
| 開始 | 初回請求月の **6ヶ月後のバッチ**から（4月開始→10月バッチで4月請求分）。`kickback_start_year_month` で上書き可 |
| 生成 | バッチ請求月 M に対し **M-6 のカスタマー請求**を対象。未入金でも金額0で作成。入金済なら税込入金額で按分 |
| 按分 | `キックバック税別 = レイヤ差額 × (入金税込 / 請求税込)`。超過入金は1.0超可 |
| 端数 | 管理者がキックバックへ明細「端数調整」（税込1円単位・税率0・マイナス可）を登録。`manual_adjusted` |
| 更新 | カスタマー請求の入金／入金金額修正時に再計算。手動再生成も可（手動調整済みは force 時のみ上書き） |
| 取下げ | カスタマー請求取下げ時、紐づくキックバックも自動取下げ |
| 価格レイヤ | **初回価格承認時にスナップショット**し、**価格変更承認のたびに更新** |
| ステータス | `issued` / `paid` / `withdrawn`（表示: **発行済** / **入金済** / **取下げ**） |
| エラー時 | **その契約だけスキップ**し他契約は続行。エラー有無が一覧・ダッシュ等で分かる |
| 参照 | ルートはエンドユーザー単価を常時参照可。中間BPは **自区間のみ** |

## スキーマ提案

### `contracts`

| カラム | 既定 | 説明 |
|--------|------|------|
| `auto_invoice_enabled` | `true` | 月末自動生成 |
| `billing_suspended` | `false` | 請求停止 |
| `end_user_billing_disabled` | `false` | EU請求（ルート発行）無効の契約デフォルト |
| `bill_initial_in_system` | `true` | イニシャルを本システムで請求するか（契約デフォルト） |
| `kickback_start_year_month` | `NULL` | NULL時は first+6か月（M-6請求を処理するバッチ開始） |
| `recalc_on_price_change` | `true` | 価格変更後の未入金請求再計算 |

### システム設定（管理者画面）

自動請求バッチの実行スケジュールを管理者が変更できる。

| 項目 | 既定 | 説明 |
|------|------|------|
| 実行日モード | `month_end` | `month_end`（月末）／`day_of_month`（毎月N日） |
| 実行日（N） | — | モードが `day_of_month` のとき **1–31** |
| 実行時刻 | `10:00` | Asia/Tokyo（時:分） |
| 有効 | ON | OFF にするとスケジューラは動かない（契約フラグとは別） |

**存在しない日の扱い（確定）:**  
`day_of_month` で指定した N が当該月に存在しない場合（例: N=31 の 2月、N=31 の 4月）は、**その月の末日**に実行する。

保存先: `system_settings`（key=`billing_batch_schedule`）。変更は監査ログ必須。

UI: 「月末」または「毎月 ○ 日」の選択＋時刻入力、**今すぐ生成**、**生成履歴**（結果バッジ・作成請求への導線）。

Docker: `Develop` の `scheduler` サービス（`schedule:work`）が無いと自動実行されない。詳細は [deploy.md](deploy.md)。

| カラム | 説明 |
|--------|------|

### `invoices`（案A）

| 変更 | 内容 |
|------|------|
| `issuer_bp_id` | ルートBP（発行主体） |
| `owning_bp_id` | 管理BP（スコープ） |
| `source` | `auto` |
| `billing_batch_run_id` | 生成実行への FK（履歴から作成一覧へ辿る） |
| `status` | `issued` / `paid` / `withdrawn`（表示: 発行済 / 入金済 / 取下げ） |
| `due_year_month` | 請求月の翌月 |
| 金額 | **EU単価 `contract_items.unit_price`**（仕切りは使わない） |
| 一意 | 契約×請求月で有効（非 withdrawn）は1件 |

### `billing_batch_runs` / `billing_batch_errors`

| テーブル | 内容 |
|----------|------|
| `billing_batch_runs` | trigger（manual/scheduled）、status（success/partial/failed）、件数、実行者、開始／終了 |
| `billing_batch_errors` | 契約単位の失敗（phase: customer_invoice / kickback） |

### `kickback_invoices` / `kickback_invoice_lines`

- from_bp_id（上位・支払）→ to_bp_id（下位・受取）
- `source_invoice_id`（対象カスタマー請求。バッチ月の6ヶ月前）
- 金額は対象請求の税込入金額按分。未入金時は0
- 区間上値・下値・税別金額・税率・税込を明細に保持
- `billing_batch_run_id` で生成実行に紐付け
- 生成失敗時はバッチエラー＋画面で絶対値付き内訳
- 管理者は `manual_adjusted` 付きで金額手動調整可

## バッチ

1. 管理者設定のスケジュールに従い実行（月末 or 毎月N日 ＋ 時刻。既定: 月末 10:00 JST）  
2. **請求月＝実行日の YYYYMM**（当月分）。手動実行は指定月  
3. 対象契約を抽出（activated・自動ON・停止OFF・請求月範囲）  
4. EU請求が有効な明細のみでカスタマー請求生成（金額＝`unit_price`、`issuer_bp_id`＝ルート）  
5. イニシャルは開始月。未請求なら後続月でキャッチアップ  
6. キックバック開始月以降、EU請求有効明細について多段キックバック生成  
7. 計算エラーの契約はスキップし、`billing_batch_errors` と生成履歴で可視化  
8. 有効請求がある月はスキップ。取下げ済みなら再生成可  
9. 実行ごとに `billing_batch_runs` を記録（成功／一部失敗／失敗）  

## UI

| 画面 | 内容 |
|------|------|
| カスタマー詳細「請求」 | 一覧・詳細・取下げ（admin/管理BP）。カスタマーは参照 |
| 管理者: 自動請求設定 | スケジュール、今すぐ生成、**生成履歴**、次回予定 |
| 生成実行詳細 | 当該実行で作成した請求・キックバック一覧 |
| 契約 | 自動生成／請求停止／EU請求無効／イニシャル請求／キックバック開始／再計算 |
| 一覧バッジ | 提供中×請求停止、提供中×EU請求無効 |
| キックバック | 自区間の支払・受取。ルートはEU単価＋全区間可 |
| 旧手動請求 | 廃止 |
