# Phase 11 計画 — デザイン刷新

## 目的

機能追加（Phase 2〜10）で積み上がった画面・ナビ・コンポーネントを、**見た目と情報設計の観点から刷新**する。  
ビジネスロジックや DB スキーマの大幅変更は行わない。UX・アクセシビリティ・三種ポータル間の一貫性を優先する。

## 合意ステータス

| 項目 | 決定 |
|------|------|
| スコープ | **デザイン刷新のみ**（機能追加・DB大幅変更なし） |
| トーン | **管理コンソール寄り**（社外BP／カスタマーも利用するが、販促LP調ではなく業務ツールとして信頼感のある見た目） |
| UI基盤 | **Bootstrap 継続**（テーマ／トークン層で見た目を揃える。別UIキットへの乗換はしない） |
| 先行適用 | **ログイン画面 → ダッシュボード**（admin / BP / カスタマーの三種） |
| 参照 | Phase 7 共通シェル（ヘッダーナビ）を土台に磨く |

## トーン方針（詳細）

| 観点 | 方針 |
|------|------|
| 印象 | 落ち着いた業務コンソール。過剰な装飾・マーケ向けヒーローは避ける |
| 色 | ニュートラル基調＋明確なアクセント1色。エリア（admin/BP/customer）は色相で軽く区別可 |
| タイポ | 可読性優先。見出し階層を揃える（h1/h3 の乱用を是正） |
| 密度 | 一覧は情報密度を保ちつつ余白を統一。カード乱用はしない（操作単位以外） |
| 信頼感 | ログインは「どのポータルか」が一目で分かる。ブランド名を弱くしない |

## スコープ

| トラック | 内容 | 備考 |

| **B. ログイン刷新** | 三種ログインの見た目統一・モバイル | **先行** |
| **C. ダッシュボード刷新** | サマリカード・空状態・情報階層 | **先行** |
| **D. レイアウト／ナビ磨き** | ヘッダー・コンテナ幅・フォーカス／ホバー | ログイン・ダッシュと整合 |

## 含まない（後続フェーズ）

- 外部決済 / 会計連携
- メール招待・マジックリンク
- Redis / WebSocket リアルタイム
- 帳票デザイナ・版管理・Word
- 請求／キックバックの業務ロジック変更（Phase 10 の延長は別途）

## デザイントークン草案（11-0）

コーポレートカラーなし。**ニュートラル（スレート）基調＋アクセント1色（スレートブルー）**。

## 先行画面の目標UI（11-B / 11-C）

### ログイン

```text
┌─────────────────────────────────────┐
│  背景: 落ち着いた単色〜ごく薄いグラデ   │
│                                     │
│      ┌─────────────────────┐        │
│      │ ポータル名 / 種別明示  │        │
│      │ ログインフォーム       │        │
│      │ （他種別へのリンクなし）│        │
│      └─────────────────────┘        │
└─────────────────────────────────────┘
```

- 三種は**別URLのまま**（フォーム・ガード共有なしは維持）
- 見た目の「部品・余白・見出し」だけ揃える
- エラー表示・2FA入力も同トーン

### ダッシュボード

```text
[エリア名ナビ…]

  見出し（ダッシュボード）
  短い説明（任意・1行）

  ┌────┐ ┌────┐ ┌────┐   ← サマリカード（権限のあるもののみ）
  └────┘ └────┘ └────┘

  （メニュー一覧は置かない＝Phase 7 方針維持）
```

## 実装上の制約

- Blade + Bootstrap + 既存 Vite（`app.css` / `app.js`）を前提
- Livewire 画面があれば見た目のみ合わせる（ロジック変更なし）
- アクセシビリティ: コントラスト、フォーカスリング、`aria` を壊さない
- レスポンシブ: ログイン・ダッシュはモバイル幅で破綻しないこと

## 受け入れ基準（先行分）

1. admin / BP / customer のログインが**同じデザイン言語**で、種別が明確  
2. 三種ダッシュボードのカード／見出し／余白が揃っている  
3. 既存のログイン・2FA・ダッシュ表示内容（件数・リンク先）が壊れていない  
4. 機能追加・マイグレーション追加がない（CSS / Blade / 必要最小のアセットのみ）
