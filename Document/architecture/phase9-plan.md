# Phase 9 計画 — チケット管理

## 目的

Phase 6 の「問い合わせ」を **チケット管理** に再編する。受領／発行の分離、宛先ルーティング、公開範囲、ステータス、添付、未読、ダッシュボード表示を実装する。

画面表記は「チケット」に統一。権限コードは既存の `inquiry.*` を流用する。

## 合意済み方針

| 項目 | 内容 |
|------|------|
| A. メニュー | トップの **チケット管理** ドロップダウン。受領チケット / チケット発行。管理者は受領のみ |
| B. 受領 / 発行 | 受領＝自分が対応先。発行＝自組織が起票したもの（`private` は起票者のみ） |
| C. 宛先 | カスタマー→管理BP。BP→親BP（ルートは管理者）。BPのカスタマー代理起票→自BPが受領・対応 |
| D. 公開範囲 | 起票時に `organization`（自組織全体） / `private`（自分のみ）。受領側は権限者全員が閲覧可 |
| E. 管理者 | 受領のみ。代理起票はスコープ外 |
| F. ステータス | 起票 / 取下 / 受領対応中 / クローズ。履歴をメッセージタイムラインに表示 |
| G. 遷移 | 起票→取下（起票側・起票中のみ）。起票→受領対応中（受領側・初回返信で自動可）。受領対応中→クローズ（受領側）。クローズ→受領対応中（再オープン・受領側）。取下は終端 |
| H. 添付 | PNG/JPEG/GIF/HEIC/HEIF/PDF。1ファイル最大10MB、1メッセージ最大5。プレビュー不可は DL |
| I. 番号 | `TKT` + `YYYYMM` + 連番（例: `TKT202609001`）。`NumberSequence` |
| J. 未読 | スレッド単位。相手の新着があるチケット数をダッシュボード表示。プッシュ通知なし |
| K. 既存データ | 旧問い合わせは破棄してよい |

## スコープ

| 含む | 含まない |
|------|----------|
| 受領／発行一覧・起票・詳細チャット | 管理者の代理起票 |
| ステータス遷移・履歴メッセージ | メール／プッシュ通知 |
| 添付（起票時・メッセージ時） | HEIC のサーバ側 JPEG 変換 |
| 未読・ダッシュボード件数 | Redis / WebSocket |
| ナビ再編・採番 | |

## データ（案）

`inquiries` 再編:

| カラム | 内容 |
|--------|------|
| `code` | `TKT202609001` |
| `assignee_type` | `admin` \| `bp` |
| `assignee_bp_id` | 対応BP（nullable） |
| `visibility` | `organization` \| `private` |
| `status` | `submitted` / `withdrawn` / `in_progress` / `closed` |
| `opened_by_user_id` / `customer_id` / `subject` 等 | 既存相当 |

新規・拡張:

- `inquiry_message_attachments`（またはメッセージに添付メタ）
- `inquiry_reads`（ユーザー×チケットの既読）
- ステータス変更はメッセージ種別（system / status_change）で同一タイムラインに載せる
- 旧 `owning_bp_id` は `assignee_bp_id` へ移行して廃止
